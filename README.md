# low-response-label-audit

Code, protocol, and aggregate results for the article

> **When Low Response Does Not Mean No Effect: A Methodological Audit of Response-Derived Weak Supervision for Financial News**
> Kittikorn Takham, Thanayut Changruenngam, Tanaphong Prommai, Aree Binprathan, and Suthep Suantai. Submitted for publication.

The article audits response-derived fuzzy labeling (RDFL), a weak-labeling rule that sorts
news-linked stock-days into negative, low, and positive response bands from the price response and
trading volume that follow the news. Its low-response class is tempting to read as "the news had no
effect". A constructive argument and a known-truth simulation show that a small net response cannot
separate "no effect" from effects that cancel. A retrospective purged pilot on Thai bank stocks and
a locally hash-locked external replication on U.S. banks from FNSPID then test whether
RDFL-trained learners beat simple baselines. They do not.

This repository holds everything needed to check those results that can be shared: the analysis
code, the tests, the replication protocol with its freeze record, and every aggregate table and
figure behind the article. It does not hold news text or row-level market data (see
[What is not included](#what-is-not-included)).

## Quick check (no data needed)

```bash
python -m pip install -r requirements.txt
python tools/verify_release.py          # standard library only
python -m unittest discover -s tests    # 30 tests
```

`tools/verify_release.py` confirms five things:

1. every released file matches `SHA256SUMS` (on Linux or macOS, `sha256sum -c SHA256SUMS` does the same);
2. the replication lock: the archived files match the original freeze record, and each released
   locked file equals its archived original after the renaming described below;
3. the released provenance snapshots equal the archived snapshots after renaming;
4. each result folder is complete, and the code it executed is byte-identical to the code in this
   repository (each run recorded those hashes in `results/<run>/run_manifest.json` before it started);
5. every original result table in `archive.zip` equals the released table after renaming.

## Naming and the archive

The procedure had a different name when the analysis was run and when the replication protocol was
frozen on 2026-09-28 at 07:27:01 UTC. For this release, the code, the protocol text, and every output
use the name RDFL, and the name of the earlier project the code came from, which appears only in
paths, labels, and comments, is replaced by "legacy". The renaming is a byte-level substitution defined
in `tools/rename_rules.py`, with one documented adjustment in `scripts/07_power_analysis.py`: that
script derives bootstrap seeds from the length of each comparator's name, so it subtracts the extra
character of each renamed occurrence and keeps the original random streams. The project name and its
replacement have the same length.

`archive.zip`, which unpacks to `archive/`, keeps, byte for byte and under their original names, the
files as they were frozen, the original freeze record, the
provenance manifests with the released snapshots, and the original run records and aggregate outputs
of every run. `research/PREREGISTRATION_FREEZE.json` is derived from the archived record: the same
frozen time, the renamed paths, and the hashes of the renamed files. Scripts 20 and 21 check that
derived record, so they still refuse to run if any locked file changes.

Every result in `results/` was regenerated by the renamed code on 2026-10-12.
`results/RENAME_EQUIVALENCE.json` compares every output of every run, row-level predictions
included, with the original output; `tools/verify_release.py` repeats the comparison for the
aggregate tables released here.

## Reproducing the results

Each script refuses to overwrite a completed result folder. To rerun one, move the shipped folder
aside first (for example, rename `results/equivalence_power` to `results/equivalence_power_published`)
and compare the new output with it.

| Scripts | Needs | Runs from this repository? |
| --- | --- | --- |
| `01_simulation.py`, `18_simulation_extensions.py`, `23_observable_bounds.py`, `27_random_abstention.py` | nothing (synthetic data) | Yes |
| `12_equivalence_power.py`, `08_manuscript_figures.py` | the shipped aggregate tables | Yes |
| `20_fnspid_prepare.py`, `21_fnspid_replication.py` | FNSPID, downloaded as described below | Yes, after the download |
| `00_snapshot.py`, `00b_snapshot_supplement.py`, `02`, `03`, `07`, `13`–`17`, `30`, `31` | the Thai news and price snapshots | No: the data are not redistributed |
| `22_prediction_dispersion.py`, `24`–`26`, `28_block_stability.py`, `29_signal_contrasts.py` | row-level outputs of the Thai pilot and of 21 | Only with the Thai data |

`19_freeze_protocol.py` was run once, before any FNSPID outcome was computed, and refuses to run
again. Scripts 20 and 21 refuse to run if any locked file has changed. `config.json` is one of those
files. Its `source_root` entry is the authors' local path to the original project and is read only
by scripts 00 and 00b, which snapshot files from that project and cannot run elsewhere.
`25_threshold_sensitivity.py` is an exploratory analysis run after all locked results were known;
it lies outside the locked protocol (deviation 4). `26_loss_decomposition.py` and
`27_random_abstention.py` are revision analyses added in response to pre-submission review, also
after all results were known and outside the protocol (deviation 6). Scripts 28–31
(stability over time, signal contrasts and calibration coefficients, historical-mean baselines, and
the Thai data flow) were added on the same terms after a second pre-submission review (deviation 7).

## External replication data (FNSPID)

FNSPID (Dong, Fan, and Peng, KDD 2024, https://doi.org/10.1145/3637528.3671629) is distributed by its authors under
CC BY-NC 4.0. It is not included here. Download `Stock_news/All_external.csv` and
`Stock_price/full_history.zip` from `https://huggingface.co/datasets/Zihan1004/FNSPID` into
`external/fnspid/`, then run

```bash
python scripts/20_fnspid_prepare.py
python scripts/21_fnspid_replication.py
```

The replication protocol (`research/PREREGISTRATION_r6.md`) was frozen on 2026-09-28 at 07:27:01
UTC, after only the counts and dates in `research/FNSPID_INSPECTION.json` had been inspected. The
freeze is local: it rests on the SHA-256 hashes in the freeze record and on the history of this
repository, not on a third-party registry. Deviations from the protocol are listed in
`research/PREREGISTRATION_DEVIATIONS.md`.

## What is not included

- **Thai news text and price panels.** They remain under their sources' terms. The SHA-256 of every
  snapshot used is listed in `archive/provenance/manifest.json` and
  `archive/provenance/supplement/manifest.json` inside `archive.zip`, so anyone who obtains the same files can confirm
  they are identical.
- **Row-level derived files.** Stock-day predictions, weak-label tables, and article-level staleness
  scores are withheld because they are derived row by row from the data above or from FNSPID.
- **FNSPID and every row-level file derived from it.** Scripts 20 and 21 regenerate them locally.
- **Simulation checkpoints.** Script 01 regenerates them.
- **Two files of an earlier project** that play no part in the article: a model fine-tuning script,
  which run identities hash but no run executes, and that project's data-audit report (the audit
  counts themselves are in `provenance/historical/p0_audit/audit.json`). Their SHA-256 values stay in
  `archive/provenance/manifest.json` inside `archive.zip`.

## Status of the evidence

This is a retrospective methods study, not a public preregistration. The Thai pilot is exploratory:
publication timestamps, the official trading calendar, price adjustment, and near-duplicate events
could not all be verified (Table S6 of the supplementary materials gives the status of each check). A confidence
interval that spans zero is reported as inconclusive, not as evidence of no effect. The ±2%
equivalence margin is a disclosed project choice.
